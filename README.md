# default_chatbot

Telegram-бот для автоматизации канала и связанного с ним чата обсуждений.

Бот подписывает опубликованные посты именем администратора, добавляет инлайн-клавиатуру со ссылками и эмодзи в комментариях и наводит порядок в чате (открепление сообщений, удаление стикеров, дедупликация комментариев для медиа-альбомов).

## Возможности

- **Автоподпись постов** - при публикации или редактировании поста в канале бот дописывает к тексту/подписи фиксированный "футер" (например, ссылку на канал).
- **Подпись автора в комментариях** - под форварднутым постом в чате обсуждений бот отвечает сообщением с именем администратора, который опубликовал пост.
- **Инлайн-клавиатура** - кнопки со ссылками (чат, буст, владелец и т.д.) добавляются к ответам бота.
- **Дедупликация альбомов** - если в посте несколько фото/видео (media group), бот отвечает в комментариях только один раз, а не по разу на каждый файл.
- **Безопасное редактирование альбомов** - бот меняет только общую подпись альбома и не добавляет подписи к каждому фото или видео по отдельности.
- **Расширенный аудит** - публикации, редактирования, удаления, сервисные события канала, реакции, изменения участников и прав, заявки на вступление и бусты отправляются в отдельный лог-чат.
- **Автооткрепление и очистка** - форварднутые из канала сообщения в чате автоматически откручиваются от закрепа; стикеры, приходящие вместе с форвардом, удаляются.
- **Уведомления об ошибках** - при исключении в хендлерах бот присылает администратору сообщение с текстом ошибки.
- **Кастомные эмодзи** - при наличии Telegram Premium владелец бота может включить функцию, что добавляет эмодзи в кнопки и сообщения бота.
- **Админ-панель** - публикация постов с настраиваемыми кнопками.

## Структура проекта

```
.
├── main.py              # точка входа: регистрация хендлеров и запуск polling
├── bot_instance.py       # создание объекта бота и обработчика ошибок
├── config.yaml            # переменные, что будут загружены скриптом
├── config.py               # загрузчик и валидатор переменных окружения
├── state.py                 # общее состояние: дедупликация альбомов, подписи постов
├── handlers.py               # основные обработчики сообщений, панелей, кнопок и постов
├── audit_handlers.py          # Bot API-аудит событий канала
├── mtproto_audit.py            # аудит удалённых постов через журнал администраторов
├── create_mtproto_session.py    # одноразовая авторизация MTProto-аккаунта
├── keyboard.py                 # инлайн-клавиатура с кнопками-ссылками
├── requirements.txt           # зависимости проекта
├── media_ids.json            # id медиа файлов (создается при 1-м запуске)
├── resources/*              # ресурсы бота (GIF изображения)
└── .github/workflows/      # автодеплой на сервер при пуше в main
```

## Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone git@github.com:damnurmum/default_chatbot.git
cd default_chatbot
```

### 2. Создать виртуальное окружение и поставить зависимости

```bash
python3 -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Настроить переменные окружения

Создайте файл `.env` в корне проекта:

```env
BOT_TOKEN=токен_вашего_бота
CHAT=id_чата_обсуждений
CHANNEL=id_канала
ADMIN=id_администратора_для_уведомлений_об_ошибках
LOG_CHAT=id_чата_для_аудита_изменений
API_ID=id_приложения_с_my.telegram.org
API_HASH=hash_приложения_с_my.telegram.org
```

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен бота, выданный [@BotFather](https://t.me/BotFather) |
| `CHAT` | ID чата обсуждений, привязанного к каналу |
| `CHANNEL` | ID канала, посты которого обрабатывает бот |
| `ADMIN` | ID пользователя, которому бот шлёт сообщения об ошибках |
| `LOG_CHAT` | ID чата, куда бот отправляет все события аудита |
| `API_ID` | ID Telegram-приложения для MTProto-аудита удалений |
| `API_HASH` | Hash Telegram-приложения для MTProto-аудита удалений |

> ID чата/канала можно узнать, например, через [@userinfobot](https://t.me/userinfobot) или пересылкой сообщения боту с `message.chat.id` в логах.

### Какие события попадают в аудит

- новые и отредактированные посты, включая фото, видео и альбомы;
- удалённые посты (при наличии MTProto клиента) и альбомы с текстом или подписью, типом медиа, ID и именем удалившего администратора;
- закрепления, смена названия и другие сервисные события канала;
- обычные реакции: смена списка доступных в настройках канала;
- вступление, выход, блокировка, назначение администраторов и изменение их прав;
- изменение прав и статуса самого бота;
- заявки на вступление;
- добавление, изменение и снятие бустов.

Для событий Bot API бот должен быть администратором канала. Для заявок на вступление ему также требуется право приглашать пользователей. `API_ID` и `API_HASH` можно создать в разделе API development tools на [my.telegram.org](https://my.telegram.org/apps). Они относятся к Telegram-приложению, а не к токену бота.

Telegram разрешает читать журнал администраторов только обычным пользовательским аккаунтам. Поэтому удаления читает отдельный MTProto-клиент с аккаунтом, который также является администратором канала. Клиент работает в фоновом потоке рядом с основным polling. При первом запуске старые удаления пропускаются, после чего бот сохраняет последний обработанный event ID в `deletion_audit_state.json`.

После добавления `API_ID` и `API_HASH` один раз создайте пользовательскую сессию:

```bash
cd /root/default_chatbot
venv/bin/python create_mtproto_session.py
chmod 600 deletion_audit.session
systemctl restart telebot_default_chatbot.service
```

Скрипт попросит номер телефона, код из Telegram и пароль двухэтапной аутентификации, если он включён. Используй обычный Telegram-аккаунт администратора канала. Файл `deletion_audit.session` даёт доступ к аккаунту, поэтому не отправляй его другим людям и не добавляй в Git. Сессионный файл и checkpoint уже добавлены в `.gitignore`.

Если `API_ID` или `API_HASH` не настроены, основной бот продолжит работать, но отправит администратору предупреждение, что аудит удалений отключён. После настройки убедитесь, что в `config.yaml` параметры `audit.all.enable` и `audit.deletion.enable` включены (по умолчанию выключен именно `audit.deletion.enable`).

### 4. Настроить основную настройку бота
Откройте и отредактируйте файл `config.yaml` в корне проекта:

| Настройка | Описание |
|---|---|
| `signs` | Группа настроек подписей |
| &nbsp;&nbsp;`signs.post.text` | Текст подписи, что будет добавляться в конец постам Telegram канала |
| &nbsp;&nbsp;`signs.comment.text` | Текст подписи, что будет добавляться к комментарию под постом (поддерживает плейсхолдер `[SIGN_ADMIN]` - имя администратора, опубликовавшего пост) |
| &nbsp;&nbsp;`signs.comment.custom_emoji` | Включить (`True`) / Выключить (`False`) кастомные эмодзи в кнопках комментария (под постами) - при включении необходим Telegram Premium на аккаунте владельца бота |
| `commands` | Группа настроек команд бота |
| &nbsp;&nbsp;`commands.start.text` | Сообщение, которое будет отправлено пользователю в ЛС при команде `/start` |
| &nbsp;&nbsp;`commands.start.custom_emoji` | Включить (`True`) / Выключить (`False`) кастомные эмодзи в кнопках меню (команды `/start`) - при включении необходим Telegram Premium на аккаунте владельца бота |
| `audit` | Группа настроек аудита действий в чате |
| &nbsp;&nbsp;`audit.all.enable` | Включить (`True`) / Выключить (`False`) полный аудит действий (открепление сообщений, удаление стикеров, дедупликация комментариев для медиа-альбомов) |
| &nbsp;&nbsp;`audit.deletion.enable` | Включить (`True`) / Выключить (`False`) аудит удалений сообщений |
| `files` | Группа путей к служебным файлам |
| &nbsp;&nbsp;`files.media_ids` | Путь к файлу, в котором хранятся `file_id` медиафайлов (например, GIF-анимаций, настраиваемых в `config.py`) - создаётся автоматически при первом запуске |
| &nbsp;&nbsp;`files.audit.session` | Путь к файлу сессии аккаунта, используемого для аудита удалений |
| &nbsp;&nbsp;`files.audit.state` | Путь к файлу состояния аудита удалений |

> **Примечание:** Настройка GIF-анимаций (`START_COMMAND_GIF`, `COMMENT_GIF`) по-прежнему выполняется в файле `config.py`, как описано в предыдущем разделе.

> **Обратите внимание!** Некоторые настройки требуют Telegram Premium на аккаунте владельца бота. Значения `file_id` медиа будут получены через отправку админу при первом запуске.

### 5. Запустить

```bash
python main.py
```

## Деплой на сервер

Проект настроен на автоматический деплой через **GitHub Actions**: при пуше в ветку `main` сервер (VDS) сам подтягивает изменения, обновляет зависимости и перезапускает бота через `systemd`.

Для работы автодеплоя на сервере должны быть настроены:
- `systemd` - сервис для бота (автозапуск и автоперезапуск при падении);
- скрипт `deploy.sh` (`git pull` → `pip install` → `systemctl restart`);
- секреты репозитория `VDS_HOST`, `VDS_USER`, `VDS_SSH_KEY` (Settings → Secrets and variables → Actions).
